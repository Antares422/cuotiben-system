# Feature Specification: 错题的筛选搜索、掌握状态与分类管理（迭代 2）

**Feature Branch**: `feat/iteration-2`

**Created**: 2026-10-03

**Status**: Draft

**Input**: User description: "错题本系统迭代 2：让用户能在错题多起来之后快速找到并复习。包括三块能力：(1) 错题列表的筛选与搜索；(2) 掌握状态标记；(3) 学科与知识点标签管理。对应 PRD 第 4 节 F3、F5、F7。F6（错题编辑与删除）和 F8（导出）不在本迭代。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 在大量错题里快速找到想复习的题 (Priority: P1)

用户已经录入了几十甚至上百道错题。复习前，他想只看"数学"里带"函数"标签、还没掌握的题，或者想起某道题里出现过"配方"两个字，想直接搜出来。他在列表页选择学科、标签、掌握状态，或输入关键字，列表立刻只显示符合条件的错题，仍然按录入时间从新到旧排列，并且可以继续翻页。

**Why this priority**: 错题本的价值在于"考前聚焦薄弱环节"。录入的题越多，不能筛选搜索就越没法用，这是迭代 1 之后最先暴露的问题，也是 PRD F3 的完整版。

**Independent Test**: 先录入分属不同学科、带不同标签、内容各异的若干错题；在列表页分别用学科、标签、关键字筛选，每次结果都与预期的那几道题完全一致；组合条件时结果是各条件的交集。

**Acceptance Scenarios**:

1. **Given** 本子里有数学、英语、物理三个学科的错题，**When** 用户选择学科"数学"，**Then** 列表只显示数学的错题，且总数显示为数学错题的数量。
2. **Given** 有的错题带标签"函数"，**When** 用户选择标签"函数"，**Then** 列表只显示带该标签的错题。
3. **Given** 用户已选择学科"数学"和标签"函数"，**When** 再选择掌握状态"未掌握"，**Then** 列表只显示同时满足三个条件的错题。
4. **Given** 某道错题的内容含"配方"、另一道的错误原因含"配方"、第三道的答案含"配方"，**When** 用户搜索"配方"，**Then** 这三道题都出现，不含"配方"的题不出现。
5. **Given** 筛选结果超过一页，**When** 用户点"加载更多"，**Then** 追加的仍是符合同一筛选条件的错题，顺序仍是从新到旧。
6. **Given** 当前筛选条件下没有任何错题，**When** 列表加载完成，**Then** 显示"没有符合条件的错题"并提供一键清除筛选的入口，而不是显示"本子还是空的"。
7. **Given** 用户设置了筛选条件，**When** 点进某道错题的详情再返回，或刷新页面，**Then** 之前的筛选条件仍然保留。

### User Story 2 - 把已经学会的题标记为"已掌握" (Priority: P1)

用户复习时逐条查看错题，把真正理解了的题标记为"已掌握"，没学会的保持"未掌握"，下次复习就只看未掌握的。他可以直接在列表里点一下完成标记，也可以在详情页里标记。标记错了可以改回。

**Why this priority**: 这是 PRD F5，是复习闭环的核心动作；没有它，"未掌握"的筛选就没有意义，所有错题永远是未掌握。

**Independent Test**: 打开一道未掌握的错题，标记为已掌握，列表和详情里的状态立刻变化；刷新后依然是已掌握；再改回未掌握，状态随之恢复。

**Acceptance Scenarios**:

1. **Given** 一道"未掌握"的错题，**When** 用户在列表页点击标记为已掌握，**Then** 该题立即显示为"已掌握"，不需要刷新页面。
2. **Given** 同一道错题，**When** 用户进入详情页，**Then** 详情页显示的也是"已掌握"。
3. **Given** 一道"已掌握"的错题，**When** 用户在详情页点击改回未掌握，**Then** 状态立即变回"未掌握"，列表中也一致。
4. **Given** 列表当前按"未掌握"筛选，**When** 用户把其中一道标记为已掌握，**Then** 这道题从当前列表中消失，列表总数相应减 1。
5. **Given** 标记操作未能成功（例如服务暂时不可用），**When** 用户点击标记，**Then** 显示明确的失败提示，并且该题仍显示操作前的状态，不会出现"界面显示已掌握、实际没保存"的情况。
6. **Given** 用户已标记某道题为已掌握，**When** 关闭并重新打开应用，**Then** 该题仍是已掌握。

### User Story 3 - 整理学科和知识点标签 (Priority: P2)

用户用久了之后，学科和标签会变乱：标签名打错了、同一个知识点有两个写法、不再用的学科想去掉。他想有一个地方集中整理：新增学科、改学科名、删除学科；改标签名、删除标签。无论怎么整理，已经录入的错题都不能丢，也不能让页面报错。

**Why this priority**: 这是 PRD F7（P1 级）。没有它，系统也能用，只是分类混乱后无法整理；所以排在筛选搜索和掌握状态之后。

**Independent Test**: 新增一个学科，改名，再删除；给一个学科关联错题后尝试删除，被明确拒绝并说明原因；重命名标签后，带该标签的错题全部显示新名字；删除标签后，错题仍在，只是不再带该标签。

**Acceptance Scenarios**:

1. **Given** 管理页，**When** 用户新增学科"信息技术"，**Then** 它立刻出现在学科列表中，并且录入错题时可以选到。
2. **Given** 学科"数学"下有 12 道错题，**When** 用户把它重命名为"高中数学"，**Then** 这 12 道错题都显示新名字。
3. **Given** 学科"生物"下有错题，**When** 用户尝试删除它，**Then** 被拒绝，并提示"该学科下还有 N 道错题，请先处理这些错题"，学科和错题都保持不变。
4. **Given** 学科"地理"下没有任何错题，**When** 用户删除它，**Then** 它从列表中消失，录入时也不再出现。
5. **Given** 标签"函数"被 8 道错题使用，**When** 用户把它重命名为"函数与方程"，**Then** 这 8 道错题的标签都显示新名字。
6. **Given** 标签"易错"被 5 道错题使用，**When** 用户删除该标签（删除前有二次确认），**Then** 标签消失，这 5 道错题仍然存在，只是不再带"易错"标签。
7. **Given** 已有学科"数学"，**When** 用户新增或重命名为同名学科，**Then** 被拒绝并提示"学科已存在"；标签同理。
8. **Given** 用户提交空白名称，**When** 保存，**Then** 被拒绝并提示名称不能为空。
9. **Given** 管理页，**When** 用户查看，**Then** 每个学科和每个标签旁边都能看到当前有多少道错题在使用它。
10. **Given** 用户执行新增、重命名或删除，**When** 操作因为服务暂时不可用而失败，**Then** 显示明确的失败提示，列表保持操作前的样子，所有错题和关联不受影响。

### Edge Cases

- 标签筛选时选择了多个标签：错题必须同时带有所选的全部标签才显示。
- 关键字前后有空格：自动忽略首尾空格；关键字全是空格：等同于没有关键字。
- 关键字里含有 `%`、`_`、引号等特殊字符：按普通文字原样匹配，不会报错，也不会匹配到所有题。
- 搜索英文时不区分大小写。
- 用户正在按某个标签筛选时，在管理页把这个标签删掉了：回到列表页时应当提示该标签已不存在并清除这个条件，而不是显示一个空结果或报错。
- 用户正在按某个学科筛选时，该学科被删除（它必须是空学科才能删除）：同上。
- 重命名为与自己当前名称相同：视为没有变化，不报"已存在"。
- 重命名时只改了大小写或首尾空格：首尾空格自动去掉；大小写不同的名称视为不同名称。
- 两道题几乎同时被标记：每道题的状态各自独立保存，互不影响。
- 在列表页连续快速点击同一道题的标记按钮：最终状态与最后一次成功的操作一致，不会出现重复提交造成的错乱。
- 没有任何标签时：标签筛选与标签管理区域显示友好的空状态，而不是空白。
- 默认自带的九个学科与用户自己新增的学科地位相同，同样可以改名；只有没有错题时才能删除。

## Requirements *(mandatory)*

### Functional Requirements

**筛选与搜索**

- **FR-001**: 用户 MUST 能按学科筛选错题列表，一次选择一个学科。
- **FR-002**: 用户 MUST 能按知识点标签筛选错题列表；选择多个标签时，只显示同时带有全部所选标签的错题。
- **FR-003**: 用户 MUST 能按掌握状态筛选（全部 / 未掌握 / 已掌握）。
- **FR-004**: 用户 MUST 能输入关键字，系统在错题的题目内容、正确答案、错误原因中查找包含该关键字的错题；英文不区分大小写；首尾空格被忽略。
- **FR-005**: 学科、标签、掌握状态、关键字这四类条件 MUST 能同时使用，结果是所有已设置条件的交集。
- **FR-006**: 筛选与搜索后的列表 MUST 仍按录入时间从新到旧排列并支持分页；列表顶部显示的"共 N 道"MUST 是符合条件的总数，而不是全部错题数。
- **FR-007**: 筛选结果 MUST 与实际数据完全一致：不遗漏符合条件的错题，也不混入不符合条件的错题。
- **FR-008**: 当没有符合条件的错题时，系统 MUST 显示"没有符合条件的错题"并提供清除全部筛选的入口；"本子还是空的"只用于确实没有任何错题的情况。
- **FR-009**: 筛选条件 MUST 在用户进入详情页再返回、以及刷新页面后保留。
- **FR-010**: 当筛选条件引用的学科或标签已经不存在时，系统 MUST 忽略并清除该条件，并告知用户，而不是报错。
- **FR-011**: 用户 MUST 能看到当前可选的学科和标签，以及一键清除所有筛选条件。

**掌握状态**

- **FR-012**: 用户 MUST 能在列表页把任意一道错题标记为"已掌握"，也能改回"未掌握"。
- **FR-013**: 用户 MUST 能在详情页把当前错题标记为"已掌握"，也能改回"未掌握"。
- **FR-014**: 状态变更 MUST 立即在界面上体现，并 MUST 被持久保存，重新打开应用后依然有效。
- **FR-015**: 如果状态保存失败，系统 MUST 明确提示失败，并让界面保持操作前的状态。
- **FR-016**: 当列表正按掌握状态筛选时，被改变状态的错题 MUST 立即从当前列表消失（因为它已不符合条件），总数同步更新。
- **FR-017**: 同一道错题在列表页和详情页看到的掌握状态 MUST 始终一致。

**学科与标签管理**

- **FR-018**: 用户 MUST 能新增学科、重命名学科、删除学科。
- **FR-019**: 用户 MUST 能重命名知识点标签、删除知识点标签。（标签的创建仍在录入错题时完成，不要求单独新增入口。）
- **FR-020**: 学科名称、标签名称 MUST 不为空（首尾空格自动去掉）、MUST 在各自范围内不重复；违反时给出明确提示。
- **FR-021**: 重命名学科或标签后，所有使用它的错题 MUST 立即显示新名字，不丢失任何关联。
- **FR-022**: 学科下仍有错题时，系统 MUST 拒绝删除该学科，并提示还有多少道错题在使用；学科与错题 MUST 保持原样。
- **FR-023**: 删除标签时，系统 MUST 先让用户二次确认；确认后该标签从所有错题上解除关联，错题本身 MUST 保留，不丢失任何其他信息。
- **FR-024**: 管理页 MUST 显示每个学科、每个标签当前被多少道错题使用。
- **FR-025**: 录入错题时可选的学科、以及筛选可选的学科和标签，MUST 与管理页中的最新结果一致，无需重启应用。
- **FR-026**: 任何整理操作（新增、重命名、删除）失败时，系统 MUST 给出明确提示，并保持数据不变。

### Key Entities *(include if feature involves data)*

- **错题**：用户录入的一道做错的题。有题目内容、可选的正确答案和错误原因、所属的一个学科、零到多个知识点标签、原图、掌握状态（已掌握 / 未掌握）、录入时间。
- **学科**：错题的大类（如数学、英语）。名称不重复。一个学科下可以有很多错题；只要还有错题，就不能删除。
- **知识点标签**：给错题打的细分标记（如函数、时态）。名称不重复。一道错题可以带多个标签，一个标签可以用在多道错题上；删除标签只解除关联，不影响错题。
- **掌握状态**：错题的一个属性，只有"已掌握"和"未掌握"两种，新录入的错题默认是"未掌握"。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在拥有 500 道错题的本子里，用户使用学科、标签、关键字的任意组合，能在 10 秒内找到指定的一道题。
- **SC-002**: 对任意一组筛选条件，显示的结果与按条件人工核对的结果完全一致：遗漏数为 0、误含数为 0。
- **SC-003**: 设置或清除筛选条件后，用户在 1 秒内看到更新后的列表。
- **SC-004**: 把一道错题标记为已掌握（或改回），用户在 1 秒内看到状态变化，并且重新打开应用后状态不变。
- **SC-005**: 在列表页完成一次标记，用户只需要 1 次点击。
- **SC-006**: 在所有整理操作的场景中（重命名、删除空学科、被占用学科的拒绝删除、删除标签），错题数量与内容的丢失率为 0，用户看到错误页面的次数为 0。
- **SC-007**: 被拒绝的操作（删除被占用的学科、重名、空名称）100% 给出用户能看懂的原因，且数据保持不变。
- **SC-008**: 首次使用的用户无需说明，能自行完成"按学科和掌握状态筛选出一批题"这件事（以 5 名同学试用，至少 4 人一次完成为准）。

## Assumptions

- 系统仍然是个人单机使用，没有账号体系，不需要考虑多人同时修改同一份数据。
- 迭代 1 已有的功能（拍照上传、识别、保存、列表分页、详情）保持不变，本迭代在其基础上增加能力。
- 选择多个标签筛选时取"同时具备全部标签"（交集），因为复习时通常是逐步缩小范围，如"函数"且"易错"。
- 学科一次只能选择一个（一道错题本来就只属于一个学科）。
- 关键字搜索的范围是题目内容、正确答案、错误原因三项；不搜索标签名、学科名（它们有专门的筛选），也不搜索图片里的文字。
- 关键字按"包含"匹配，不做分词、不做同义词扩展、不做拼音或错别字容错。
- 学科被错题使用时直接拒绝删除，不提供"把错题转移到其他学科"的功能；用户需要先处理这些错题（编辑和删除错题属于迭代 3 的 F6）。这样既避免数据丢失，也避免本迭代范围扩大。
- 删除标签不会删除或修改错题的其他内容；已被删除的标签不会自动恢复，需要时可在录入错题时重新创建。
- 没有任何错题使用的标签仍然保留在管理页中，直到用户手动删除，这样用户能看到并清理它们。
- 筛选条件只需要在刷新页面、前进后退、进入详情再返回时还原；不要求关闭应用后仍然记住，也不跨设备。
- 不在本迭代范围内：编辑或删除错题（F6）、导出复习清单（F8）、批量标记或批量整理、合并标签、学科与标签的排序或自定义颜色、智能推荐复习顺序。
- 依赖迭代 1 已经具备的数据：错题已带有掌握状态字段（默认未掌握），学科和标签已有各自的名称。
