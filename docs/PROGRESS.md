## 怎么分工

6 个人同时做，靠 `tasks.md` 里的 `@姓名` 认领，避免两个人做同一个任务、也避免互相覆盖。

**先决条件：组员要能往仓库推送。** 现在仓库的协作者只有组长一人。组长需要在 GitHub 仓库的 Settings → Collaborators 里把组员加进来，
否则组员推不了代码（也就无法"先推送认领"）。不想加协作者的话，组员改用 **fork 后提合并请求**，认领也通过合并请求完成。

**`main` 分支已开启保护**（2026-10-03）：

| 规则 | 效果 |
| :--- | :--- |
| 合并必须通过合并请求 | 协作者不能直接往 `main` 推送，必须开合并请求 |
| 两项 CI 检查必须通过 | 「后端（ruff + 测试）」「前端（类型检查 + 测试 + 构建）」任一为红，合并按钮不可用 |
| 需要的批准数为 0 | 不强制别人审核，自己开的合并请求，CI 绿了就能合并；想要互相审核，把它改成 1 |
| 禁止强制推送、禁止删除 `main` | 历史不会被改写 |
| **管理员（组长）不受限制** | 组长仍可直接推送到 `main`，用于合并迭代分支、打标签、紧急修复 |

**认领步骤**

1. `git pull`，看 `tools/progress.sh` 最后的「负责人」一栏，挑**没人认领**的任务。
2. 在 `tasks.md` 里给要做的任务加 `@姓名`，**只改这一行**，单独提交并立刻推送：`chore: 认领 T001–T011`。
   - 推送被拒绝，说明别人先改了：`git pull --rebase`，再看你要的任务是不是已被认领，是就换一个。
3. 建自己的分支做：`feat/<你的名字>-<主题>`，完成后开合并请求，目标是迭代分支（如 `feat/iteration-2`）。**CI 全绿**才合并。
4. 做完把该任务的 `- [ ]` 改成 `- [x]`，**和代码放在同一次提交**。
5. 想换人或放弃：改掉或删掉 `@姓名`，推送，并在群里说一声。

**建议**

- **一次认领一整个阶段或一个故事**（如 Phase 1 的 T001–T011），比逐个任务认领更不容易冲突，也更利于连续思考。
- 阶段之间的依赖见 `tasks.md` 的「依赖与顺序」：前端阶段依赖后端阶段，Phase 3 与 Phase 4 互相独立，可以由不同人并行做。
- 不要两个人同时改同一个文件（例如都改 `services/mistakes.py`）：先在群里对一下。
